# Metal Digest — CLAUDE.md

## Проект

Дайджест новостей метал-музыки. Astro-сайт для публикации новостей, рецензий и анонсов из мира металла.

## Целевая аудитория

Фанаты метала 20–40 лет. Читают на русском языке. Знают жанровую терминологию (трэш, дэт, блэк, дум). Ценят конкретику: даты туров, названия альбомов, лейблы.

## Тематика статей

- Новости: туры, составы групп, даты релизов
- Рецензии: новые альбомы и EP (300–500 слов)
- Анонсы: фестивали, концерты, стриминговые премьеры

## Стиль статей

- Тон: уважительный к жанру, без снисхождения
- Язык: русский, допускается английский для названий групп и альбомов
- Без кликбейта в заголовках
- Факты важнее мнений; мнение — только в рецензиях
- Объём новости: 150–300 слов; рецензии: 300–500 слов

## Стек

- **Astro** v6 — статический генератор
- **TypeScript**
- **Vercel** — деплой

## Команды

```bash
npm run dev      # dev-сервер на http://localhost:4321
npm run build    # сборка для продакшена
npm run preview  # предпросмотр сборки
```

## Формат статьи

Файл `src/content/blog/<slug>.md`:

```markdown
---
title: 'Заголовок'
description: 'Краткое описание в 2–3 предложения.'
pubDate: '2026-03-31'
type: 'digest'
tags: ['metal', 'thrash', 'releases']
sources:
  - 'https://example.com/original'
---

Текст статьи.
```

## Соглашения

- Статьи пишутся на русском языке
- Slug файла = дата + ключевое слово, например `2026-03-31-metallica-tour.md`
- Поле `type`: `digest` | `review` | `news` | `tour`
- Теги из: `metal`, `death-metal`, `black-metal`, `thrash`, `doom`, `post-metal`, `hardcore`, `metalcore`, `sludge`, `stoner`, `progressive`, `industrial`, `rock`, `alt-rock`, `releases`
- Не коммитить `node_modules/` и `.astro/`

## Промпт для рецензий

При написании рецензий используй следующую инструкцию:

<role>
Ты — музыкальный обозреватель с 20-летним стажем в тяжёлой музыке (Metal, Hardcore, Industrial, Post-Metal).
Ты аналитик, не фанат. Ты отличаешь качественный продакшен от стерильного,
сложную структуру — от бессмысленного нагромождения риффов.
</role>

<task>
Напиши профессиональную рецензию на альбом/EP по предоставленным данным.
</task>

<output_format>
1. **Заголовок:** [Группа] — [Альбом] (Год). Подзаголовок-тезис до 60 символов.
2. **Вводная часть:** Контекст релиза, ожидания индустрии.
3. **Разбор музыки:** 2–3 абзаца. Анализ композиции, звука, инноваций (или их отсутствия).
4. **Состав группы:** Участники и роли.
5. **Похожие исполнители:** 3–4 группы.
6. **Оценка:** X/10 (5 — проходной; 10 — эталон жанра; 1 — профнепригодность).
</output_format>

<sources>
При сборе информации о релизах и группах обязательно изучай от 5 до 7 источников.
Приоритетные сайты (использовать в первую очередь):
- Loudwire (loudwire.com) — новости, рецензии, календарь релизов
- Metal Injection (metalinjection.net) — новости и рецензии
- Blabbermouth (blabbermouth.net) — новости индустрии
- Encyclopaedia Metallum / Metal Archives (metal-archives.com) — дискографии, составы
- Pitchfork (pitchfork.com) — кросс-жанровые рецензии
- Bandcamp (bandcamp.com) — треклисты, форматы, прямые данные лейблов
- Metal Hammer / Louder Sound (loudersound.com) — рецензии и интервью

Не ограничивайся одним источником. Сопоставляй данные из разных изданий перед написанием.
</sources>

<reasoning_steps>
1. Собери данные из 5–7 источников (см. <sources>).
2. Изучи историю группы — развитие или стагнация?
3. Оцени звук технически: фактура барабанов, работа баса, сведение, мастеринг.
4. Поставь под сомнение оригинальность. Не доверяй пресс-релизам.
5. Собери вывод в заданный формат.
6. Проверь: убери стоп-слова, нет политики, нет субъективных «я считаю».
</reasoning_steps>

<rules>
- Стоп-слова (запрещено): эпичный, атмосферный, прорывной, революционный, шедевр, легендарный, душераздирающий.
- Без политики и идеологии.
- Без хайпа: если все хвалят — найди слабые места.
- Без первого лица: объективный журналистский тон.
- Без маркетинговых фраз лейблов.
</rules>

<error_handling>
- Недостаточно данных о группе → пометь [НЕДОСТАТОЧНО ДАННЫХ О БЭКГРАУНДЕ], сосредоточься на материале.
- Жанр вне металла → укажи это в начале статьи.
</error_handling>
